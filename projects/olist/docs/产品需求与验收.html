MVP 产品需求与验收（成果复盘版）

本文件根据现有功能整理，不能作为“开发前已完成需求研究/正式评审”的证据。

1. 范围

目标：支持履约风险监控和订单异常跟进。目标用户：运营、客服组长、一线客服。暂不包括自动人员分配、金融信用评级、自动物流干预和绩效结算。

2. 功能和验收

功能规则验收方式
日期和地区筛选历史日期中午 12:00；按消费者州筛选切换后所有运营 KPI 和明细口径一致
监控待送达、逾期、两天内到期、高风险；趋势、州和商家异常与相同条件的 SQL/Python 结果核对
运营总览异常混合分布、阶段分布、优先订单指标卡可进入相应队列
订单队列All pending / Overdue / Due soon / At risk；阶段筛选；订单/商家搜索条件组合正确，空结果显示提示
排序异常级别、逾期天数、风险概率、订单 ID相同条件多次查看排序稳定
订单详情风险、金额、地区、商家、品类、承诺日期与时间线不显示统计日期之后才发生的送达/交承运商事件
客服记录Open、Investigating、Contacted、Resolved；状态和备注追加保存保存后出现历史，刷新后仍可查询；Resolved 不等于已送达
CSV导出全部匹配记录，非仅页面前 25 条行数和筛选结果一致，中文/备注文本正确转义
模型效果固定留出集：策略、校准、月份、州和商家历史分组和已保存分析结果一致，不混作实时订单监控

3. 数据与存储

原系统查询原始表、predictions 和最新客服记录；SQL item_agg 先聚合订单商品，避免多表 JOIN 将金额放大。predictions 的 order_id 为主键并引用 orders；case_events 追加处理历史，并以 order_id 引用 orders。

离线演示使用完整已评分订单 SQL 导出和已保存测试结果。客服演示记录使用浏览器 localStorage，与 MySQL 记录隔离。离线说明展示在作品首页和使用文档；产品页只保留简短 Offline demo 标识。

4. 关键边界

预测概率是审核时风险，不是随日期更新的实时风险。客服状态显示最新记录，不按历史日期回溯。当前结果无法衡量真实客服干预收益；模型误报和漏报应在试点中结合处理成本评价。
